# Efficient celebration particles

The largest four-friend scene currently reaches 672 submitted draws in the sampled guardian/celebration view. Its 80 ordinary dust and confetti particles are separate meshes despite sharing one small geometry. Batch these into one fixed instanced mesh to leave more rendering room for the iPad while preserving their appearance and timing. This is a rendering and lifecycle change, with no new controls, game rules or effects.

Add an owned `BurstParticles` controller with 80 reusable slots, one existing-size icosahedron geometry, one standard material and per-instance colors. Keep the existing dust, colored confetti and gold reward palettes, gravity, spread, spin and shrinking lifetimes. A full pool submits one draw and the same active triangle count. Recompute conservative culling bounds from active instance matrices; do not allocate buffers or model objects per burst/frame.

The controller exposes `burst({kind, count, origin, enabled})`, `update(dt,{phase,mode,reducedMotion})`, `clear()`, `dispose()` and read-only diagnostics. Kinds are `celebrate`, `dust` and `reward`. The optional enabled flag defaults to the last valid update's context; GameScene supplies current permission after checking its mode and motion preference, because core events dispatch before the visual update. This prevents a missing first reward after leaving gentler motion. It owns its random source (default Math.random, injectable for tests), resources and fixed particle array. Each particle may retain an unparented Object3D transform for compatibility with current scene inspection, but only the InstancedMesh is added to the scene.

Paused and invalid/nonpositive-time frames preserve all particle state and GPU buffer versions. A running gentler-motion change removes old decorative particles as well as suppressing new ones. Explicit menu, truck replacement and replay clear old particles before changing scenes. Finish celebrations continue animating in the finished race. Resource disposal is complete, independent and idempotent.

Root will replace the existing GameScene particle loop and burst helper after the shoreline/crush-star increment is committed. Acceptance compares deterministic before/after geometry positions, colors and lifetime envelopes, all active vertices against culling bounds, fixed pool/buffer identities, exact pause and disposal, and real browser views of dust, gold crush feedback, guardian sparkles and the finish celebration. Re-measure the prior worst scene and complete race; report draw reduction without claiming unmeasured physical-device frame rates.
